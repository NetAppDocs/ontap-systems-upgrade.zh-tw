= ARL升級工作流程
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
在使用ARL升級節點之前、您必須先瞭解程序的運作方式。在本文中、程序分為幾個階段。



[[upgrade-the-node-pair]]
== 升級節點配對

要升級節點配對，您需要準備好原有節點，並在原節點和新節點上依照升級步驟進行操作。然後，將原有節點退役。



[[arl-upgrade-sequence-overview]]
== ARL升級順序總覽

您需要逐一升級原有控制器硬體與替換控制器硬體，並利用 HA 配對組態來轉移非根目錄彙總的所有權。您必須將所有非根目錄彙總轉移兩次，才能到達正確的升級節點。

每個Aggregate都有一個擁有者和目前擁有者。主擁有者是該集合體的實際擁有者、而目前擁有者則是暫時擁有者。

下圖顯示程序的各個階段。淺灰色的粗箭頭代表集合體的重新定位和生命量的移動、而較細的黑色箭頭則代表原始節點的移除。較小的控制器映像代表原始節點、較大的控制器映像則代表新節點。

image:arl_upgrade_manual_image1.PNG["顯示ARL程序各階段的圖例"]

了解您在每個階段執行的高階任務以及階段結束時的彙總所有權狀態。詳細步驟將在後續流程中提供。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["一"]link:determine_aggregates_on_internal_drives.html["階段1：準備升級"]
[role="quick-margin-para"]
在第1階段期間、如果需要、您可以確認內部磁碟機不包含根集合體或資料集合體、準備節點進行升級、並執行一系列預先檢查。如有必要、您可以重新輸入磁碟以進行儲存加密、並準備以網路方式開機新的控制器。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["二"]link:relocate_non_root_aggr_node1_node2.html["階段2：淘汰節點1"]
[role="quick-margin-para"]
在第2階段期間、您會將非根Aggregate從節點1重新部署至節點2、並將節點1擁有的非SAN資料lifs移至節點2、包括故障或遭否決的Aggregate。您也可以記錄必要的node1資訊、以便稍後在程序中使用、並淘汰node1。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["三"]link:install_boot_node3.html["階段3：安裝和開機節點3"]
[role="quick-margin-para"]
在第三階段，您需要安裝並開機 node3，並將叢集連接埠和節點管理連接埠從 node1 對應到 node3。如果您使用 NetApp Volume Encryption （NVE），則需要還原金鑰管理器組態。然後，將屬於 node1 的資料 LIF 和 SAN LIF 從 node2 遷移到 node3，將所有彙總從 node2 遷移到 node3，並將 node2 擁有的資料 LIF 和 SAN LIF 遷移到 node3。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["四"]link:record_node2_information.html["第4階段：淘汰節點2"]
[role="quick-margin-para"]
在第4階段期間、您會記錄必要的node2資訊、以便稍後在程序中使用、然後淘汰node2。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["五"]link:install_boot_node4.html["階段5：安裝和開機節點4"]
[role="quick-margin-para"]
在第五階段，您需要安裝並開機 node4，並將叢集連接埠和節點管理連接埠從 node2 對應到 node4。如果您使用 NetApp Volume Encryption （NVE），則需要還原金鑰管理器組態。然後，將屬於 node2 的資料 LIF 和 SAN LIF 從 node3 遷移到 node4，將 node2 的彙總資料從 node3 遷移到 node4，並將 node2 擁有的資料 LIF 和 SAN LIF 遷移到 node3。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["六"]link:manage_authentication_kmip.html["第6階段：完成升級"]
[role="quick-margin-para"]
在第6階段期間、您確認新節點已正確設定、如果新節點已啟用加密、則可設定儲存加密或NetApp Volume加密。您也應該取消委任舊節點、並恢復SnapMirror作業。
